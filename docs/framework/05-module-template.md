**Author:** Vinod Jadhav  
**Programme:** MSc Artificial Intelligence - University of Essex

---

# Status

Reusable Template

This document defines the standard structure that I will follow when developing each module section within my e-Portfolio.

The purpose is to ensure consistency across the MSc programme while allowing each module to include its own unique evidence and reflections.

---

# Purpose

Each module produces different types of evidence such as discussions, practical activities, projects, presentations, and reflections.

Rather than designing a different structure for every module, I will use this template as the standard framework for organising my learning and evidence.

This helps ensure that:

- every module follows a consistent format;
- evidence is easy to locate;
- learning outcomes are clearly demonstrated;
- reflections are supported by practical examples;
- assessment requirements are addressed systematically.

---

# Standard Module Structure

## 1. Module Overview

Provide a brief introduction to the module.

Include:

- purpose of the module;
- key topics studied;
- relevance to Artificial Intelligence.

---

## 2. Learning Outcomes

Summarise the official learning outcomes.

Where appropriate, briefly explain what each outcome meant in practice during the module.

---

## 3. Learning Journey

Provide a short overview of how my understanding developed throughout the module.

This section should describe the overall learning experience rather than individual activities.

---

## 4. Collaborative Learning

Include:

- Initial discussion posts;
- Peer responses;
- Summary posts.

For each discussion:

- brief overview;
- key learning points;
- evidence;
- personal reflection.

---

## 5. Unit Activities

Include practical activities completed during the module.

Examples:

- coding exercises;
- modelling activities;
- diagrams;
- laboratory work;
- research activities.

For each activity include:

- objective;
- output;
- evidence;
- learning gained.

---

## 6. Team Activities

Where applicable include:

- team meetings;
- design discussions;
- collaborative documents;
- individual contribution;
- lessons learned.

---

## 7. Individual Project

Where applicable include:

- planning;
- implementation;
- testing;
- evaluation;
- screenshots;
- GitHub repository;
- presentation;
- supporting documents.

---

## 8. Evidence Gallery

Provide links or screenshots of important artefacts.

Examples:

- GitHub repositories;
- diagrams;
- testing evidence;
- project screenshots;
- presentations;
- reports.

---

## 9. Feedback

Summarise feedback received from:

- classmates;
- tutors;
- project supervisors.

Describe how this feedback influenced my work.

---

## 10. Professional Skills Development

Summarise the skills developed during the module.

Examples include:

- communication;
- teamwork;
- critical thinking;
- research;
- programming;
- problem solving;
- ethical awareness;
- project planning;
- time management.

---

## 11. Professional Development Plan (PDP)

Identify:

- strengths developed;
- areas requiring improvement;
- actions for future learning.

---

## 12. Reflective Commentary

The reflection should focus on:

- knowledge gained;
- technical development;
- challenges encountered;
- personal growth;
- future improvements.

Where appropriate, use the University's recommended reflective structure.

### What?

Describe the activity or experience.

### So What?

Explain why it was important.

### Now What?

Describe how this learning will influence future work.

---

## 13. Learning Outcome Mapping

For each major activity, identify which learning outcomes it demonstrates.

This ensures that the portfolio directly supports the assessment requirements.

---

## 14. References

Include all references using the required Harvard referencing style.

# Before Publishing

Before updating the HTML page, I will confirm that:

✓ The evidence supports the learning outcomes.

✓ The reflections are genuine and evidence-based.

✓ The writing follows my Writing Guidelines.

✓ The content aligns with the assessment criteria.

✓ References have been included where required.

✓ Screenshots and artefacts are correctly linked.

---

# How I Will Use This Template

For every new module, I will:

1. Copy this structure.
2. Review the module assessment brief.
3. Remove sections that are not applicable.
4. Add any module-specific requirements.
5. Populate the sections with evidence collected during the module.
6. Review the content against the marking criteria before publishing it on my GitHub e-Portfolio.

This approach ensures that every module follows a consistent structure while remaining flexible enough to accommodate different assessment requirements.
