# Purpose

The purpose of this document is to define a consistent framework for developing my e-Portfolio throughout the MSc programme.

Rather than treating the e-Portfolio as a collection of individual assignments, I want it to become a structured record of my learning journey, practical work, reflections, and professional development.

This document provides the overall strategy that I will follow for every module so that the portfolio remains organised, consistent, and aligned with the University assessment guidance.

---

# Why I Created This Blueprint

When I started building my GitHub Pages website, I realised there were many different types of evidence produced during each module, including discussion posts, practical activities, coding exercises, team projects, reflections, meeting notes, presentations, and final assignments.

Without a clear structure, it would become difficult to organise this material and to demonstrate how it relates to the module learning outcomes.

Creating this blueprint allows me to:

- organise my work consistently across every module;
- map evidence directly to learning outcomes;
- ensure that every section contributes towards the assessment criteria;
- maintain a record of my professional development throughout the MSc programme;
- reuse the same structure for future modules.

---

# Portfolio Philosophy

I want my e-Portfolio to tell the story of my learning rather than simply storing completed coursework.

Each module should demonstrate:

- what I studied;
- what practical work I completed;
- how my understanding developed;
- what challenges I encountered;
- how I applied theoretical concepts;
- how I intend to improve in future.

The emphasis is on continuous learning and reflection rather than presenting only successful outcomes.

---

# Guiding Principles

While developing this e-Portfolio I will follow the following principles.

## 1. Evidence First

Every statement should be supported by evidence wherever possible.

Examples include:

- discussion forum contributions;
- practical exercises;
- coding activities;
- screenshots;
- testing results;
- design documents;
- GitHub repositories;
- presentations;
- tutor or peer feedback.

---

## 2. Reflection Before Description

Instead of only describing what I completed, I will explain:

- what I learned;
- why it was important;
- what difficulties I experienced;
- how my thinking changed;
- how I would improve in future.

---

## 3. Learning Outcomes Drive the Content

Every major section should demonstrate one or more module learning outcomes.

This ensures that the portfolio directly supports the assessment requirements rather than becoming a simple collection of coursework.

---

## 4. Authentic Writing

The portfolio should reflect my own learning journey.

As someone transitioning from an enterprise networking background into Artificial Intelligence, my reflections should honestly describe both my strengths and the areas where I am still developing.

The aim is to produce a genuine academic portfolio rather than an overly polished report.

---

# Standard Module Structure

Each module will follow the same overall structure wherever appropriate.

1. Module Overview

2. Module Learning Outcomes

3. Learning Journey

4. Collaborative Discussions

5. Unit Activities

6. Team Exercises

7. Individual Project

8. Evidence Gallery

9. Team Meeting Notes

10. Feedback from Peers and Tutors

11. Professional Skills Matrix

12. Reflective Case Studies (where applicable)

13. Final Reflection

14. References

---

# Standard Workflow

Every piece of work added to the portfolio should follow the same process.

```
Module Activity

↓

Collect Evidence

↓

Review Learning Outcomes

↓

Review Assessment Guidance

↓

Write Reflection

↓

Map Reflection to Learning Outcomes

↓

Update e-Portfolio

↓

Review Against Assessment Criteria

↓

Commit to GitHub

↓

Publish GitHub Pages
```

Following the same workflow for every module helps ensure consistency across the entire programme.
